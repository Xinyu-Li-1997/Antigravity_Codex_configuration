# `user-guard` 架构设计与生命周期钩子规范

本文档说明反重力（Google Antigravity）与 OpenAI Codex 双端生命周期钩子的事件协议、核心状态机、边界检查算法与实机验收记录。日常使用与安装流程见[仓库总 README](../README.md)和[协作实践指南](反重力全域工程化最佳实践指南.md)。

## 一、 反重力钩子编排总览

反重力原生插件通过插件根目录下的 `hooks.json` 注册同步命令钩子（`type: "command"`）。钩子进程从标准输入（`stdin`）读取 **camelCase** JSON 载荷，向标准输出（`stdout`）返回单行 JSON 响应（官方协议参考[反重力钩子文档](https://antigravity.google/docs/hooks)）。

运行时宿主会自动注入两个环境变量：
- `PLUGIN_ROOT`：插件代码安装目录（如 `~/.gemini/config/plugins/user-guard`）；
- `PLUGIN_DATA`：插件专属运行态数据目录（如 `~/.gemini/antigravity/plugin_data/user-guard`）。

`user-guard` 将会话状态（`state/`）与运行日志（`logs/`）统一存放在 `PLUGIN_DATA` 下，做到运行数据与插件代码彻底分离。

### `hooks.json` 标准结构

```json
{
  "user-guard-lifecycle": {
    "SessionStart": [
      {
        "type": "command",
        "command": "python3 -X utf8 -I -B ./hooks/session_context_loader.py --event SessionStart",
        "timeout": 30
      }
    ],
    "PreInvocation": [
      {
        "type": "command",
        "command": "python3 -X utf8 -I -B ./hooks/session_context_loader.py --event PreInvocation",
        "timeout": 30
      }
    ],
    "PreToolUse": [
      {
        "matcher": ".*",
        "hooks": [
          {
            "type": "command",
            "command": "python3 -X utf8 -I -B ./hooks/status_guard.py",
            "timeout": 15
          }
        ]
      }
    ],
    "Stop": [
      {
        "type": "command",
        "command": "python3 -X utf8 -I -B ./hooks/reply_repeat_guard.py",
        "timeout": 15
      }
    ]
  }
}
```

> **跨平台 Python 命令适配**：`install.py` 部署时会自动探测当前系统 PATH 中可用的 Python 3.9+ 解释器（Windows 探测 `python.exe` 或 `py.exe -3`，Linux／macOS／WSL 优先探测 `python3`），重写钩子命令前缀；若 PATH 中无可用解释器则直接报错中止，避免写入失效路径。

## 二、 四大核心守护模块规范

### 1. 压缩与续接的用户原话回溯（`session_context_loader.py` + `user_words.py`）

#### （1）反重力侧：增量字节游标状态机（`<convId>_compaction.json`）
反重力通过 `SessionStart` 处理会话初始化，通过 `PreInvocation` 增量检测轨迹中新出现的 `"type": "CHECKPOINT"`。即便宿主传入 `transcript_full.jsonl`，脚本也会优先定位同目录下的紧凑轨迹 `transcript.jsonl` 做增量扫描与体积统计，只在遇到 `truncated_fields` 时按步骤号回查 `transcript_full.jsonl` 补全正文。

状态文件记录以下核心字段：
- `scannedByteOffset` 与 `scannedTranscriptName`：上次扫描到的文件字节偏移量与轨迹文件名；
- `latestCheckpointStep` 与 `lastInjectedCheckpointStep`：已观测到的最新检查点步骤号与已完成注入的检查点步骤号；
- `hasExplicitUserInput`：是否含人类显式输入（纯后台子代理会话不触发主会话原话注入）。

每次调用仅从 `scannedByteOffset` 向后读取新增字节：
1. **未发生新压缩的常规轮次**：更新游标并直接返回 `{"injectSteps": []}`；
2. **新检查点出现后的首轮**（`latestCheckpointStep > lastInjectedCheckpointStep`）：
   - 提取全部用户显式输入（匹配外层 `<USER_REQUEST>...</USER_REQUEST>` 及调用 ID 可关联的多选回答），遇到截断字段时从 `transcript_full.jsonl` 还原；若完整轨迹缺失或仍截断，则在归档中如实标明缺口；
   - 更新 `<PLUGIN_DATA>/state/<convId>_user_words.md`，并在预算上限内（总长 `8,000` 字符、单条 `1,200` 字符，超长时保留首轮立项与最近若干轮指令）构造含归档路径指针的 `systemMessage` 注入上下文；
   - 若 `<convId>_handoff_gate.json` 意外损坏，异常会被隔离记录到日志，绝不中断原话恢复主流程。

#### （2）Codex 侧：多段 Rollout 合并归档（`--client codex`）
Codex 在压缩或恢复会话时触发匹配 `^(compact|resume)$` 的 `SessionStart` 钩子，传入 `session_id` 与当前 `rollout-*.jsonl` 路径。针对同一逻辑会话可能跨多个归档与活动分段（含 `archived_sessions/`）的情况：
1. 先核对 `session_meta`、会话 ID 与子代理标记，确认属于主会话后再处理；
2. 按消息角色与来源（provenance）过滤系统自动注入块，保留真实用户输入、附件引用与可关联选项答复；
3. 在会话文件锁保护下成对写入 Markdown 归档与 SHA-256 校验清单；若历史分段缺失或校验不一致，保留已有可恢复内容并标明缺口。

### 2. `PreToolUse` 目录硬边界与防空转轮询门禁（`status_guard.py`）

#### （1）项目外写删拦截（落实 R4）
钩子从 `workspacePaths`（回退 `cwd`）获取当前项目根目录，检查文件写入工具与 `run_command` 中的外部写删目标：
- **正常放行区域**：当前项目根目录（含 Windows `<盘符>:/...` 与 WSL `/mnt/<盘符>/...` 等价挂载路径）、系统真实临时目录（`%TEMP%`、`/tmp`，须通过物理路径校验防软链接逃逸）、宿主会话记忆／轨迹／制品草稿目录及标准 `.cache` 缓存区；
- **AST 与 Shell 子句解析**：对 `python -c`／heredoc 等内联脚本使用 Python `ast` 分析写删调用（识别 `Path.home()`、`open(..., 'w'|'a'|'x'|'+')`、`.write_text`、`os.remove`、`shutil.rmtree` 等），对 Shell 命令先剥离 `wsl`／`bash -lc`／`powershell -Command` 包装再按子句识别重定向、写删命令与 `sed -i`／`perl -i` 目标文件（自动跳过引号内 `>` 字符与 `sed`/`perl` 脚本表达式参数，避免误报）；
- **分级处置**：
  - **交互主会话**：返回 `{"decision": "force_ask", "reason": "..."}`，弹窗列明当前意图、写删动作、外部目标路径与命令片段供用户审批；
  - **无头子任务**（`CAE_HARNESS_DEPTH=1`）：对越界调用直接返回 `{"decision": "deny", "reason": "..."}`。

#### （2）日志复合指纹防空转轮询
仅针对日志文件（`.log`、`.out`、`.err`、`.output`、特定任务结果文件及 `.system_generated/tasks|steps/`）启用指纹比对，不干扰普通源码与业务配置读取：
- 区分不同行号范围与不同查询命令（如先 `grep` 后 `tail` 正常放行，同参数原地重复轮询且文件未变时才拦截）；
- Windows 下通过 `wsl`／`ssh`／`docker` 查看宿主机不可见的容器／子系统内部路径时自动放行；
- 大文件采用头尾分块哈希避免卡顿：
  $$\text{Fingerprint} = \begin{cases} (\text{mtime\_ns},\ \text{size},\ \text{SHA256}_{\text{full}}), & \text{size} \le 4\ \text{MiB} \\ (\text{mtime\_ns},\ \text{size},\ \text{SHA256}_{\text{head 1MiB} \parallel \text{tail 1MiB}}), & \text{size} > 4\ \text{MiB} \end{cases}$$

### 3. `Stop` 防同质等待刷屏门禁（`reply_repeat_guard.py`）

- **防死循环双保险**：若 `continuationActive == true`（当前正处于钩子触发的续跑轮）或终止原因属于运行错误，直接返回 `allow`；每个用户回合最多触发 1 次拦截。
- **保留数值进展**：逆序扫描紧凑轨迹锁定当前回合最新模型回复（单回合超 `256 KiB` 时自动分块向前溯源）。若短回复含等待词且无提问请示，提取带数字的归一化签名比对：只要迭代步数、残差或时间步等数值发生了真实变化（如从 `100 步` 更新到 `500 步`），即视为有效进展放行；仅在连续 3 次内容完全同质且无数值推进时返回 `continue` 提醒静默等待。

### 4. 双端长会话交接门禁（`handoff_gate.py`）

#### （1）反重力侧：预警 -> 排空（`drain`） -> 冻结（`freeze`）
1. **分级启发式阈值**：
   - **Stage-1（`advisory` 预警，不阻断操作）**：压缩达 `11` 次、紧凑轨迹达 `4 MiB`、`6` 次压缩后近 3 段平均间隔 `<= 90` 步、读图达 `35` 次／`50 MiB`，或 `cp >= 6` 且媒体步数达 `60`；
   - **Stage-2（`drain` 排空期）**：宿主发出真实历史截断信号、用户明确下达交接指令、压缩 `>= 16` 次、`cp >= 10` 且近 3 段平均间隔 `<= 75` 步、紧凑轨迹 `>= 6 MiB`、读图 `>= 65` 次／`100 MiB`，或 `cp >= 6` 且媒体步数 `>= 160`。
2. **排空与冻结行为**：
   - 进入 `drain`/`freeze` 后立即禁止新派生子代理、`cae_harness.py` 新任务、`git push`、后台常驻进程与图片读取；
   - `drain` 期保留最多 `4` 次模型调用与 `8` 次局部收尾动作预算，耗尽后转入 `freeze`（仅放行只读核对、项目内交接文档写入、本地 `git add`/`git commit` 与必要收尾工具）；
   - 用户明确发送“先别交接，继续当前对话”时按 R8 进入 `overridden` 宽限期（延后 `3` 次压缩与 `120` 步）；
   - `Stop` 阶段核验本轮确实更新了结构完整的交接文档，或最终回复包含完整交接四要素（已验证进展、Git 状态、未完成事项及围栏代码块形式的【新对话提示词】，支持编号标题与冒号引导行）；若启用了 `/goal`，末行须独立输出 `<!-- GOAL_CANCELLED -->`。

#### （2）Codex 侧：默认 `advisory` 提醒与可选 `enforce` 严格收口
`handoff_gate.py --client codex` 挂载在 `PostCompact`、`SessionStart(compact|resume)`、`UserPromptSubmit`、`PreToolUse` 与 `Stop` 五类事件上（参考[Codex 钩子文档](https://learn.chatgpt.com/docs/hooks)）：
- 默认采用 `advisory` 模式（压缩阈值 `0`），只记录压缩次数并注入提醒，绝不强行阻断工具或回合；
- 显式开启 `enforce` 且达到设定阈值或收到明确交接指令时，按 `4` 次收尾动作排空后转入 `freeze`（仅放行只读命令、项目内交接文档 `apply_patch` 与本地提交），并在 `Stop` 阶段校验交接内容（最多要求补正 1 次，随后结束当前回合）。

## 三、 跨平台编码与并发文件锁规约

1. **全链路 UTF-8 标准流**：所有钩子均以 `-X utf8 -I -B` 启动，并在入口显式执行 `reconfigure(encoding="utf-8", errors="replace")`，杜绝 Windows 管道 ANSI 乱码与 Linux `LANG=C` ASCII 报错。
2. **原子写盘与跨平台文件锁**：状态文件与归档统一先写同目录临时文件，`flush()` + `os.fsync()` 后通过 `os.replace()` 原子替换（Windows 下对瞬态 `PermissionError` 做短退避重试）。并发读写采用标准库操作系统级文件锁（Windows `msvcrt`／POSIX `fcntl`），Codex 原话归档与交接状态使用独立锁域避免互相阻塞。

## 四、 受控实机验收记录（2026-11-13）

以下记录均在本机独立临时目录中实测验证，原始轨迹与回执留存本地，公开文档仅保留脱敏后的关键结论。

### 1. 生命周期钩子与跨端执行实测
- **Codex CLI `0.167.0-alpha.4.1`（Windows）**：
  - `advisory` 模式五类事件全部真实触发，手动与低阈值自动压缩计数准确，跨进程 `resume` 不重复累加；
  - 隔离进程启用 `enforce` 模式后，成功拦截 `drain` 期推送及 `freeze` 期普通源码补丁，放行 `4` 次局部收尾动作与项目内交接文档 `apply_patch`，`Stop` 阶段正确覆盖“一次补正后通过”与“未补齐安全停机”两条分支。
- **反重力 CLI `1.5.8`（Windows 与 WSL `Ubuntu-24.04`）**：
  - 四类生命周期事件（`SessionStart`、`PreInvocation`、`PreToolUse`、`Stop`）在双平台均原生触发；明确交接指令进入 `drain`、完成交接后 `Stop` 正常放行；
  - WSL 原生 CLI 登录并沿用交互环境代理后，`cae-harness` 只读与 `Hydrogen (High)` 写入任务均以纯 Linux 原生链路（`side=posix`、`windows_interop=false`）一次通过固定体积三单元周期通量差的 9 组精确分数验收（耗时 `49.64s`）；
  - `Orchestrator (Carbon)` 首次跨端调用因上游流式 `unexpected EOF` 重试叠加 `300s` 外层时限超时，将单次上限调至 `900s` 后于新临时目录 `342.07s` 完成同一通量验收。
