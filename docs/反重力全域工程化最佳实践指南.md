# Codex 与反重力工程和科研协作实践

本指南说明 `user-guard` 与共享 `cae-harness` 技能的任务分工、输入预算、回执核验及 Windows／WSL 同步方式。具体命令见[共享技能](../template/user-guard/skills/cae-harness/SKILL.md)，安装入口见[仓库说明](../README.md)。

## 项目主责与任务交接

| 项目侧重 | 总控 | 独立协作职责 |
| --- | --- | --- |
| 代码工程 | Codex | 反重力校正方向、润色技术表述并独立验收 |
| 科研主题 | 反重力 | Codex 完成其中部分高质量编码和数学工作 |

主责按用户确定的项目或阶段安排。总控拆分独立任务，核实返回的原始证据并组织交付。方法选择、物理假设和适用范围仍按用户的裁决推进。

两种方向共用同一套脚本与结果格式。派工任务单须写清用户最新定论、输入基线、工作目录、允许改动的文件范围、交付形式和验收命令；由于跨端调用运行在独立的无头 CLI 进程中，它看不到主桌面会话里的聊天上下文与外部插件连接器，所需背景信息均应通过任务单明确传入。

## 两级模型架构与专长分级选路（一级总控 + 二级并发流）

本体系区分**交互总控层（一级）**与**并发协同执行层（二级）**，二者互不冲突：
- **一级（前端交互总控优先）**：用户可在桌面端／IDE 优先选用 `Orchestrator (Carbon)`／`Orchestrator (Argon)` 等混动路由按钮（在单回合内自动将常规读写检索步骤卸载给高速执行模型、核心规划与判断保留旗舰思考）或直选纯高阶深思模型作为交互总控；该选择由宿主前端管理，不会破坏或干扰二级并发工作流。
- **二级（并发流自适应／显式／模糊选路）**：`cae-harness`（`agy` 与 `codex`）及只读子代理作为二级执行层，默认策略（`--tier auto`、`:default`）在运行期动态读取两侧可用模型目录元数据，实行**“模型因地制宜按专长选路、思考挡位按任务性质分级”**：
  - **模型因地制宜按专长匹配**：
    - **深度推理与数理攻坚**（`math`、`direction` 及含证明／守恒／稳定性推导的攻坚复核）：自动排除含 `flash`、`hydrogen`、`lite`、`mini`、`fast` 标签的轻量高速家族与混动路由器（`orchestrator`、`router`），锁定目录中定位最难推理任务的旗舰深思模型（若输入规模超出专长模型窗口阈值则自动回退大窗口工程主力）；
    - **大窗口代码实现与全量审计**（`code`、`audit`、`gate`、常规 `review` 与 `polish`）：自动匹配默认优先级最高、非轻量非混动的大上下文工程主力模型；
    - **快速轻量巡检**（`low` 挡表面核查或显式省额度／快速扫查）：自动匹配同代轻量高速模型家族（含新一代 `hydrogen` 以及 `flash`/`lite`/`mini`），避免倒挂回退至旧代低效模型；
    - **显式精确与模糊别名指定**：支持通过 `--engine <后端>:<模型全名/显示名/模糊别名>`（如 `--engine "agy:Orchestrator (Carbon)"`、`--engine agy:carbon`、`--engine agy:orchestrator-argon`、`--engine codex:<模型别名>`）或自然语言提示词明确点名（如“请调用 Argon 模型”“使用混动 Orchestrator 路由”，内置 CFD 物理名词防误触过滤）明确覆写默认选路；
    - **长周期稀缺配额池保护**：宿主内共享长周期稀缺配额的跨厂商内置模型默认排除在后台自动选路之外，仅在用户或总控显式指定时调用。
- **思考挡位（Reasoning Effort）分级与防套娃裂变**：
  - **单模型纯思考最高挡（`max`／`xhigh`）**：用于 `math`、`direction`、含高阶数值格式／守恒律／并发根因特征的任务、大规模跨多文件审查，以及 `gate` 首轮验收未通过后的排错重试轮；**后台无头子任务默认跳过会触发内部二次自动派生委派的挡位（如 `ultra`）**，防止“子任务内再套娃派生子任务”导致额度倍增与超时；
  - **高挡（`high`）**：用于边界清晰的常规代码实现（`code`）、常规审查与审计分片、`gate` 首轮执行及长篇技术润色；
  - **中／低挡（`medium`／`low`）**：不含复杂推导的短篇纯文字润色自动采用 `medium` 挡（避免过度推敲引发无声放大），单文件拼写／缩进／注释表面核查自动采用 `low` 挡；
  - **显式指令覆盖**：任务描述明确指定挡位（含否定前缀识别，如“不要低档”不会误降挡）或命令行显式传入 `--tier ultra|max|xhigh|high|medium|low` 时按显式要求执行。每次调用的实际模型、推理挡位与选路来源（`profile_source`）均随 JSON 回执透明披露。

`probe` 默认读取静态环境信息与本地模型缓存；加上 `--discover-models` 会主动查询 CLI 最新模型列表并刷新本地缓存。阅读探测回执时，请注意区分“找到可执行文件”“本地配置／缓存里记录的容量”“认证状态”与“真实调用已验证通过”四类不同层级的事实——模型能否实际调通，最终以对应 CLI 的真实执行回执为准。

两条 CLI 调用各自使用对应工具的认证和计费配置。日常按既定分工自动按需发起协作以降低人工调度成本；一旦某一方返回额度或用量上限，`cae-harness` 立即终止同批后续请求、返回 `quota_exhausted`（退出码 `5`），并将解析出的恢复时间写入本侧运行缓存（`cae_quota_state.json`）。冷却期内再次触发调用时，脚本在真正发请求前自动拦截（`preflight_blocked: true`），由当前总控提示用户选择先不发起（改由本侧直接完成）或在充值／恢复后附带 `--retry-quota` 重试（调用成功后自动清除冷却记录）。本机制仅调用用户在本地通过官方渠道安装并登录的 `agy` 与 `codex` CLI，不接入其他命令行工具、非官方第三方接口或外部 SDK。

### 会话列表与项目树隔离

双向自动化派工默认不向对侧桌面端侧边栏生成机器格式的子任务对话条，也不会拆分或新增项目树目录：
- **反重力调用 Codex**：固定传递 `codex exec --ephemeral --skip-git-repo-check -C <目标目录>`，不写入 `~/.codex/sessions`、不向 `state_5.sqlite` 追加侧边栏对话线程，也不向 `~/.codex/config.toml` 的 `[projects]` 写入临时或子目录条目。
- **Codex 调用反重力**：固定通过 `agy` 无头模式运行，会话记录仅落入 `~/.gemini/antigravity-cli`，与反重力桌面端／IDE 使用的 `~/.gemini/antigravity` 会话库物理分离，且不会在 `~/.gemini/config/projects/` 下创建新项目配置。
- **统一主线留痕**：分片审计与结构化协作产生的所有结论、行号证据及变更报告均汇总回当前总控所在的唯一阶段主对话，避免机器指令碎片淹没人工工程会话。

## 上下文容量与覆盖范围

| 信息 | 能够说明的内容 |
| --- | --- |
| 本地窗口配置 | 用户或客户端配置的目标容量 |
| 模型缓存中的容量 | 缓存记录的模型元数据，需结合版本和配置解释 |
| 输入预算 | 为安排任务而使用的估算，来源和预留策略随回执披露 |
| 真实执行证据 | 本次实际读取范围、输出、压缩情况和失败信息 |

源码字节数只能用于初步估算。工具输出、系统指令、JSON Schema、推理和最终答案也占用上下文。`--codex-input-budget` 和 `--agy-input-budget` 允许按任务调整估算预算，默认策略值随探测结果说明。

`single-pass` 将预算允许的文件安排在一个审计任务中，旧 `whole-1m` 参数作为兼容别名处理。完整读取与无压缩分析需要本次执行证据确认。遇到超出预算、不可读或被跳过的文件，总控检查清单和原因，再确定补充任务。

分片审计保留每片的文件范围。跨模块全局变量、边界通量、雅可比耦合或符号约定可能横跨多个分片，总控应将这些依赖作为联合复核问题。单片结论的适用范围以实际输入为准。

## 只读协作与代码实现

| 入口或角色 | 用途 |
| --- | --- |
| `readonly-reader` | 长文件通读和精确摘录 |
| `readonly-auditor`／`audit` | 文件、公式、数字和审计发现的核验 |
| `readonly-collaborator`／`task` 的只读类型 | 方向建议、润色文本、数学推导及一般复核 |
| `task --kind code` | 明确范围的代码实现及可选验证 |
| `gate` | 修改后执行指定验收命令，按限定轮次修复 |

反重力只读角色仅开放读取、检索及结构化回执收尾接口（`[read_file, search_web, finish]`，禁止文件修改与命令执行），Codex 只读调用选择 `-s read-only` 沙箱模式。执行前后比较工作区文件状态，发现写入时如实报告。工具权限和状态比较分别承担执行限制与结果核查的作用。

代码任务用 `--write-scope` 描述允许写入的文件，可重复指定。执行后核对真实变更集，越界报告由总控处理。这项检查发生在写入之后，调用方须为异常情况保留实际差异并检查原有未提交修改。

### 双侧项目目录硬边界约束

任何项目除用户明确下达指令批准外，反重力与 Codex 均严禁在当前项目根目录之外的业务目录或宿主机全局配置中创建、修改、移动或删除任何文件或目录（包括严禁向父目录或外部路径创建 `.codex-worktrees`／`git worktree`、改动其他项目目录或擅改宿主机全局配置；系统标准临时目录、宿主与项目关联的对话记忆／子代理轨迹／制品草稿目录及标准 `.cache` 工具缓存区正常放行）：
- **反重力侧**：`PreToolUse` 钩子（`status_guard.py`）基于内联 Python AST 语法树与 Shell 子句命令头配对，精准识别对项目外业务路径或全局配置的写删改操作（零只读误报，兼容跨端 `<盘符>:/...` 与 `/mnt/<盘符>/...` 同项目路径及软链接／目录联接逃逸检测）。交互主会话触发真实越界时返回 `force_ask`，在弹窗清晰展示**当前任务意图、具体写删动作、项目外目标路径与触发语句**请求用户明确批准；无头子任务（`CAE_HARNESS_DEPTH=1`）直接硬阻断（`deny`）。
- **Codex 侧**：安装器默认将本机 `~/.codex/config.toml` 的 `sandbox_mode` 收紧为 `"workspace-write"`、设置 `approval_policy = "on-request"` 并开启 `[sandbox_workspace_write] network_access = true`，由操作系统级沙箱将直接写入限制在当前工作区与系统临时区内，任何越界业务目录或全局配置写删操作均强制触发审批提示；`cae-harness` 子任务则显式传入 `-s read-only|workspace-write -c approval_policy="never"`，严禁静默逃逸至项目外。

验收命令由任务明确给出。编译成功、守恒残差、网格收敛、时间步收敛和物理模型验证分别有自身判据，使用与问题定义相符的检查和容差。

## 进度、失败与取消

标准错误流提供生命周期事件，标准输出提供最终 JSON。父会话保留自己启动的进程句柄，使用事件观察进度，并等待最终状态。

成功、部分完成、输出无效、超时和失败分别处理。返回内容需要满足对应结构，执行器失败与验收结果均进入判断。总控检查回执中的已完成范围、错误原因和工作区差异后决定补做事项。

取消与超时处理针对本次派生的进程树。任务完成后，最终结论仍需总控核对。跨程序独立调用的进程状态与现有桌面对话的状态分别由各自宿主管理。

## 生命周期恢复与后台计算

反重力 App、IDE 和 CLI 使用本侧用户级插件目录。Windows 与 WSL 的用户配置和会话目录各自管理，插件源码从同一提交安装。

`session_context_loader.py` 在 `SessionStart` 与 `PreInvocation` 中增量检测检查点，利用可取得的轨迹生成用户原话恢复入口；当前总控按 `R9` 重读用户原话，对照摘要和文件状态，再汇报已完成与待交付事项。在此基础上，`handoff_gate.py` 协同 `status_guard.py` 与 `reply_repeat_guard.py` 构成反重力专有两阶段“原子收口＋交接停机”硬门禁（`R9.4`）：当长会话出现压缩频次／间隔坍塌、多模态批量读图过载或前端历史截断提示时，依次触发 Stage-1 纯提醒（`advisory`）与 Stage-2 排空冻结（`drain` -> `freeze`，禁新开派工与继续读图、限定手头原子单元闭环与交接写盘／`git commit`，`Stop` 校验交接产物与 `/goal` 的 `<!-- GOAL_CANCELLED -->` 终止标记，支持 `R8` 显式暂缓）。钩子协议、阈值标定与归档方式见[生命周期钩子规范](架构设计与生命周期钩子规范.md)。

长耗时数值任务按本机资源约束在 WSL 或独立计算环境执行。总控统一安排共享计算资源和写入范围，按运行宿主提供的后台完成通知或进度事件继续工作。重复状态查询与同质回复由现有钩子检查。

## Windows 与 WSL 版本同步

1. 将待验证改动形成明确的 Git 提交，记录当前工作区差异。独立复核使用该提交及实际测试结果。
2. Windows 和 WSL 分别在临时目录运行安装器：单端验证可用 `--app antigravity --target-dir <临时插件目录> --no-zotero` 或 `--app codex --codex-home <临时Codex目录> --no-zotero`；双端联合验证可同时传入两者。
3. 两侧运行离线回归，核对脚本与技能内容一致，检查本侧 Python 命令、CLI 路径及参数。真实调用测试另行记录运行版本、模型、输入和回执。
4. 当前任务进入合适间隙后，从已验收提交更新各侧用户目录。Codex 技能安装与反重力插件安装共享同一份源码，配置和认证按对应运行环境解析。

WSL 优先选择本侧已登录的原生 CLI。当 WSL 未安装原生 `codex` 或原生 `agy` 未登录时，自动通过跨子系统进程监督回退调用 Windows 侧已登录的 `codex.exe`／`agy.exe`（读取对应 Windows 用户配置）：`/mnt/<盘符>` 共享目录可直接在沙箱内完成只读与授权写入任务，WSL 纯 Linux 文件系统路径（转换后为 `\\wsl.localhost\...` UNC 路径，受 Windows 受限令牌沙箱阻断）在只读任务与审计中会自动按相对路径临时镜像至 Windows `%TEMP%` 完成审查，而代码写入任务会提前明确阻断并提示改用 `/mnt/<盘符>` 工作区或在 WSL 使用已登录的原生 CLI。

遇到网络、认证或模型访问错误时，保留对应错误状态和来源，再定位本侧配置。环境诊断与业务任务的代码修改分别按本次授权范围处理。

官方接口可查阅 [Codex 非交互模式](https://learn.chatgpt.com/docs/non-interactive-mode)、[Codex 技能](https://learn.chatgpt.com/docs/build-skills)和[反重力无头模式](https://antigravity.google/docs/cli/headless)。
